# Writing a Blog Post

## Overview

이 레포(yonghaklee.github.io)의 기존 관례에 맞는 한국어 포스트를 `_posts/` 에 작성한다.
관례는 추측하지 말고 기존 포스트에서 확인한다.

## Workflow

### 1. 시리즈 판단

```bash
ls _posts/
```

주제가 기존 시리즈에 속하면, 그 시리즈의 가장 최근 파일을 **읽고** 아래를 그대로 승계한다.
묻지 않는다.

- 파일명 패턴과 다음 순번
- `title` 의 번호 표기 방식
- `categories`, `tags`

속하지 않으면 새 시리즈로 보고 `categories` / `tags` / 슬러그를 정해 2단계에서 확인받는다.

### 2. 확인 질문 (최대 2개)

기존 포스트에서 추론할 수 있는 것은 묻지 않는다. 아래일 때만 묻는다.

- 새 시리즈라 `categories` 배치가 갈릴 때
- 주제가 넓어 한 편에 담을지 나눌지 갈릴 때

물을 게 없으면 바로 3단계로 간다.

### 3. 날짜 구하기

실행해서 나온 값을 그대로 쓴다. 날짜도 시각도 지어내지 않는다.

```bash
TZ="Asia/Seoul" date +"%Y-%m-%d %H:%M:%S %z"
```

파일 경로는 그 결과의 날짜 부분을 쓴다: `_posts/YYYY-MM-DD-<슬러그>.md`

### 4. 분량 정하기

같은 시리즈 글의 실제 분량을 재고 그 범위 안에서 쓴다.

```bash
wc -c _posts/<같은-시리즈-파일들>
```

시리즈 최대치를 넘기지 않는다. 주제가 그 안에 안 들어가면 **범위를 좁히거나 편을 나눈다.**
분량을 늘려서 해결하지 않는다. 참고로 linux 시리즈는 1.6~8KB, GIU 시리즈는 3~24KB,
cs231n 시리즈(원문 번역)는 39~125KB다.

### 5. 작성

frontmatter 형태:

```yaml
---
title: 04. 파일 접근 권한 관리
date: 2025-08-28 17:19:21 +0900
categories: [OS, Linux]
tags: [study, linux]
---
```

- `math: true` 는 수식을 쓸 때만, `mermaid: true` 는 mermaid 를 쓸 때만 추가한다
- `description` 은 긴 글에만 추가한다
- `image`(커버 이미지), `pin`, `toc` 는 쓰지 않는다

본문은 아래 House Style 을 따른다. Chirpy 고유 문법(prompt 박스, 이미지 정렬, 각주,
파일명 라벨 붙은 코드블록, 수식, mermaid)이 필요하면 `chirpy-syntax.md` 를 읽는다.

### 6. 검증

```bash
.claude/skills/writing-blog-post/check-post.sh _posts/<파일명>
```

ERROR 가 하나라도 나오면 고치고 다시 실행한다. `OK` 가 나올 때까지 반복한다.
WARN 은 읽고 판단한다.

### 7. 보고

파일 경로, 섹션 구성, 사용자가 직접 확인해야 할 부분(사실관계가 불확실한 대목)을 알린다.
커밋하지 않는다.

## House Style

기존 `_posts/` 에서 추출한 규칙이다.

| 항목 | 규칙 |
|---|---|
| 문체 | 한국어 서술체(`~한다`, `~이다`). 존댓말·구어체 금지 |
| 분량 | 같은 시리즈의 기존 글 범위 안. 넘치면 편을 나눈다 |
| 섹션 | `## N. 제목` 으로 번호를 매기고, 섹션 사이에 `---` 구분선을 넣는다 |
| 하위 섹션 | `### N.M 제목` 또는 번호 없는 `### 제목` |
| 도입·마무리 | 없다. 첫 `##` 섹션부터 바로 본론이고, 마지막 섹션에서 끝난다 |
| 제목 | 본문에 H1(`# `) 금지. `title` 이 H1 이다 |
| 목차 | 본문에 목차 금지. Chirpy 가 사이드바에 자동 생성한다 |
| 문단 | 2~4줄. 길어지면 불릿으로 쪼갠다 |
| 코드 | 코드블록에 언어를 반드시 지정한다 (bash, python, yaml 등) |
| 인라인 | 명령어·파일명·옵션·값은 백틱으로 감싼다 |
| 용어 정의 | 정의 리스트를 쓴다 |
| 용어 | 영어 기술 용어는 번역하지 않고 원문 그대로 쓴다 |

정의 리스트 형태:

```markdown
`SetUID`
: 파일이 실행되는 동안 파일 소유자의 권한으로 실행되도록 한다.
```

## Red Flags

작성 중 아래 생각이 들면 관례를 벗어나고 있다.

| 생각 | 실제 |
|---|---|
| "오늘 날짜는 대충 이거일 것" | 날짜도 시각도 `date` 명령을 실행해서 확인한다 |
| "날짜만 맞으면 시:분:초는 아무거나" | 시각까지 실행 결과 그대로 쓴다 |
| "관련 내용이니 이것도 넣어두자" | 시리즈 분량을 넘기면 편을 나눈다 |
| "빠짐없이 다루는 게 친절하다" | 기존 글은 한 편에 한 주제만 다룬다 |
| "도입부로 배경을 설명하자" | 도입부 없음. 바로 첫 섹션에서 시작한다 |
| "마지막에 정리 문단을 넣자" | 없음. 마지막 섹션에서 끝난다 |
| "목차를 넣으면 친절하겠다" | Chirpy 가 사이드바에 만든다 |
| "커버 이미지가 있으면 보기 좋겠다" | 이 블로그는 쓰지 않는다 |
| "존댓말이 읽기 편하겠다" | 기존 글 전부 서술체다 |
| "기존 포스트는 안 봐도 알겠다" | 1단계에서 실제로 읽는다 |
